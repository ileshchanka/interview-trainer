# Interview Trainer

Тренажёр для подготовки к собеседованию. Два направления на выбор (переключатель в шапке):

- **Web** — JavaScript, TypeScript, Angular;
- **Android** — Kotlin, Android SDK, Compose, корутины и Flow.

Два режима в одном приложении:

- **Карточки с интервальным повторением** (алгоритм SM-2) — 456 вопросов с ответами
  и разборами. Чем увереннее ответ, тем дольше карточка не вернётся.
- **Кодовая песочница** — 49 задач формата «что выведет этот код».

Прогресс хранится локально в IndexedDB, бэкенда нет.

### Почему задачи двух видов

JavaScript и TypeScript **по-настоящему исполняются** в браузере, и предсказание сверяется
с фактическим выводом. Kotlin исполнить нечем: JS-движок его не понимает, а транспилятор
Kotlin→JS весит десятки мегабайт и всё равно не даёт Android SDK. Поэтому андроид-задачи
показывают код только для чтения и сверяют ответ с записанным в JSON — и приложение говорит
об этом прямо, не притворяясь, что запускает код.

Чтобы записанный ответ был правдой, `npm run verify:content` компилирует и запускает каждую
Kotlin-задачу настоящим `kotlinc`. Одна из двадцати одной была записана неверно и нашлась
именно так.

## Запуск

```bash
npm install
npm start           # http://localhost:4200
```

## Проверки

```bash
npm run check           # всё сразу: контент, тесты, сборка
npm run verify:content  # структура корпуса + фактический вывод всех задач
npm test                # юнит-тесты
npm run build
```

`verify:content` — не формальность: он **исполняет** каждую кодовую задачу и сверяет
результат с записанным в JSON. JS и TypeScript выполняются в изолированном контексте Node,
Kotlin — через `kotlinc` (`brew install kotlin`; без него скрипт не падает, а предупреждает,
сколько задач осталось непроверенными). Библиотека корутин скачивается один раз
в `node_modules/.cache/kotlin`.

Четыре задачи из сорока девяти были записаны неверно и найдены именно так.

## Устройство

```
src/app/
  domain/     чистый TypeScript без Angular: SM-2, отбор сессии, сравнение вывода, треки
  core/       хранилище прогресса (IndexedDB за интерфейсом) и загрузка контента
  features/   экраны: колоды, повторение, задачи, статистика
  shared/     обёртка Monaco, Markdown, тема, выбранный трек
public/content/
  web/        js.json  ts.json  angular.json  tasks.json
  android/    kotlin.json  android.json  compose.json  coroutines.json  tasks.json
```

Состав треков задан один раз в `src/app/domain/tracks.ts`; загружается всегда ровно один
трек, поэтому фильтрация по нему на экранах получается сама собой — чужих карточек
в памяти просто нет.

Ключевое решение: **вся логика повторений и проверки ответов живёт в `domain/` —
чистых модулях без Angular, DOM и сети**. Они полностью покрыты юнит-тестами на
синтетических данных, а Angular-слой только рисует их результат.

Стек: Angular 22 (standalone, signals, zoneless change detection, lazy-роутинг),
Angular Material, Monaco, TypeScript в строгом режиме, Vitest.

### Как исполняется код задач

Решение выполняется в **Web Worker** с таймаутом в 3 секунды: `while (true) {}` —
типичная ошибка в задачах про event loop, и на главном потоке она вешала бы вкладку.
Воркер главный поток не блокирует, а по таймауту его убивает `terminate()`.

TypeScript транспилируется **самим Monaco** — компилятор приезжает вместе с редактором,
и тащить в проект второй экземпляр `typescript` ради стирания типов незачем.

## Пополнение корпуса

Вопросы и задачи — статические JSON в `public/content/<трек>/`. Добавили карточку — запустите
`npm run verify:content`. Идентификаторы стабильны и не должны меняться:
по ним привязан накопленный прогресс.

Новая тема добавляется в `src/app/domain/tracks.ts` и в таблицу `TRACKS` внутри
`scripts/verify-content.mjs`, после чего рядом кладётся файл `<тема>.json`.
